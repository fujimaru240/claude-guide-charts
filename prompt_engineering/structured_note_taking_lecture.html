なぜ必要か

問題：コンテキストウィンドウの限界
会話が長くなると古い情報は圧縮・消去される。Claudeは「さっき決めたこと」を忘れ、作業の一貫性が崩れる。
解決：外部ファイルへの永続化
重要情報を構造化されたファイルに書き出し、会話のたびに参照させる。「記憶」をコンテキストに依存しない。
情報の劣化プロセス
初回会話完全な文脈・決定事項・コード
→
中盤古い部分が要約・圧縮される
→
後半初期の決定を「忘れた」状態で作業継続
構造化ノートが解決する問題
一貫性
方針・仕様の変更が常にファイルに反映
再開性
翌日・翌週でも即座に文脈復元
追跡性
何を決めたか・なぜ決めたかが残る
圧縮耐性
要約されても核心情報は失われない

ノートの構造設計

3層アーキテクチャ
L1 コンテキスト層 変わらない前提
目標・制約・ステークホルダー
L2 状態層 現在の進捗
決定事項・未解決課題
L3 作業ログ層 最近の変更
試行錯誤・次アクション
更新頻度の設計
L1 コンテキスト
低（方針変更時のみ）
L2 状態
中（決定事項ごと）
L3 作業ログ
高（ステップごと）
ファイル分割の考え方
project/ ├── CONTEXT.md ← L1 ├── STATUS.md ← L2 ├── WORKLOG.md ← L3 └── DECISIONS.md ← 意思決定記録
単一ファイル派
シンプルなタスクはNOTE.md 1本でOK。セクション区切りで3層を実現。

分割ファイル派
長期・複雑なプロジェクト向け。Claudeに「まずSTATUS.mdを読め」と指示しやすい。

ノートテンプレート

基本テンプレート（NOTE.md）
# PROJECT NOTE ## [CONTEXT] 変わらない前提 - 目標： - 制約： - 技術スタック： - ステークホルダー： ## [STATUS] 現在の状態 - 進捗フェーズ： - 完了済み： - 未解決の課題： - 現在の方針・決定事項： ## [WORKLOG] 直近の作業 ### YYYY-MM-DD - やったこと： - 判明したこと： - 次のアクション： ## [OPEN QUESTIONS] 未解決事項 - [ ] 質問/課題（優先度：高/中/低）
DECISIONS.md（意思決定専用）
# DECISION LOG ## DEC-001 YYYY-MM-DD 決定内容： 〇〇を採用する 背景： 〇〇という制約があり、Aは△△のため却下 影響範囲： 〇〇モジュール全体 再検討条件： 〇〇が変わった場合

自動更新プロンプトテンプレート

設計のポイント
Claudeに「いつ・何を・どう更新するか」を明示的に判断させるための3要素：
① トリガー条件（どんな状況で更新するか）
② 更新対象と形式（何をどのフォーマットで書くか）
③ 更新の判断基準（何が「重要」かのルール）
システムプロンプト組み込み型（毎回参照版）
## ノート管理ルール 作業中、以下の条件を満たしたら NOTE.md を自律的に更新せよ。 【更新トリガー】 以下のいずれかが発生したら即座に更新： 1. 方針・仕様・技術選択を決定した 2. 重要なエラー原因が判明した 3. ユーザーが要件を変更・追加した 4. フェーズの区切り（実装→テスト等）を迎えた 【更新ルール】 - [CONTEXT] は原則変更しない（ユーザー確認後のみ） - [STATUS] は「現在の真実」のみを保持。過去情報は削除 - [WORKLOG] は上位追記（最新が先頭）、7日以上前は削除 - [OPEN QUESTIONS] は解決済みを即チェック 【更新の書き方】 ``` [NOTE更新] - 更新セクション：STATUS - 変更内容：〇〇を△△に変更 - 理由：〇〇が判明したため ``` と宣言してからファイルを更新すること。
セッション開始時プロンプト
## セッション開始手順 新しい会話を始めるとき、必ず以下を実行： 1. NOTE.md を読み込み、現在の状態を把握 2. 以下のサマリーをユーザーに提示： ``` [状態確認] 現フェーズ：〇〇 前回の作業：〇〇 未解決課題：〇〇（件） 今回の優先タスク候補：〇〇 ``` 3. ユーザーの今回の目的を確認 4. 作業完了後、NOTE.md を更新してセッションを終了
更新判断プロンプト（タスク埋め込み型）
以下のタスクを実行せよ： {タスク内容} ## 実行後に必ず行うこと タスク完了後、下記の問いに答えてNOTE.mdを更新： Q1: 今回の作業で「決定したこと」があるか？ → あれば [STATUS] の決定事項に追記 Q2: 「判明したこと・学んだこと」があるか？ → あれば [WORKLOG] に追記 Q3: 「新しい未解決事項」が生まれたか？ → あれば [OPEN QUESTIONS] に追加 Q4: 既存の情報で「古くなった・間違い」はあるか？ → あれば該当箇所を削除・修正
